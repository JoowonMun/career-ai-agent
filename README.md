# career-ai

**근거 기반 지원 서류 작성 에이전트.** 채용 공고를 넣으면 기업·직무를 분석하고, 내 경험 기록에 근거해 공고 맞춤 경력기술서와 자기소개서 초안을 만든 뒤 교정·글자수 검증을 거쳐 Notion에 정리합니다.

> 자동으로 지원하지 않습니다. 모든 초안은 사람이 확인하고 고친 뒤 직접 제출하는 것을 전제로 합니다.

## 왜 만들었나

이직을 준비하며 공고마다 기업 조사, 경험 고르기, 글자수 맞추기를 반복했습니다. LLM에 맡기면 빨라지지만, **없는 경험이나 수치를 그럴듯하게 지어내는** 문제가 있었습니다. 그래서 목표를 "편하지만 사실과 다르지 않은 초안"으로 잡았습니다.

## 동작 흐름

```
공고 입력(원문·URL·이미지)
 → 기업·직무 분석 (DART 공시, 뉴스, 공고 본문, 직무 해석)  [사람 확인 ①]
 → 강조 전략 → 맞춤 경력기술서
 → 문항별 설계표 (전략가 에이전트 두 명이 따로 내고 비교)   [사람 확인 ②]
 → 자기소개서 초안                                         [사람 확인 ③]
 → 확정 뒤 문체 교정 한 번 → 글자수·제목 검증 → Notion "지원 현황" 정리
```

직접 쓰거나 고친 자소서는 `/review`로 채용 담당자 관점의 평가를 받고, 대화하며 필요한 곳만 고칩니다.

## 핵심 설계

| 문제 | 해결 |
|---|---|
| LLM이 경험·수치를 지어냄 | 경험 기록에 있는 사실만 쓰기, 문장마다 근거 파일 주석, 저장 전 근거 대조, 교정·축약 뒤 원본과 사실 대조 |
| 그럴듯한 인과·시행착오를 덧붙임 | 근거 파일에 없는 이전 상태·원인·과정을 쓰지 않는 규칙과 검사 단계 (샘플 테스트에서 실제로 발견해 추가) |
| 문항마다 같은 경험 반복 | 공고 기준 강조 전략 → 문항 유형(직무역량, 협업, 실패·성장 등)별 소재 배분. 한 경험은 한 문항의 주 소재로만 |
| 소재 고르기가 결과 크기에 끌려감 | 채용 컨설턴트 역할의 전략가 에이전트 두 명이 관점(문항 우선, 스토리 우선)을 나눠 문항별 설계표(보려는 것, 주 소재, 핵심 장면, 구체적으로 쓸 것, 줄일 것)를 따로 내고, 비교해 하나를 고름 |
| 문항이 무엇을 보는지 놓침 | 문항마다 평가 초점(인성·역량) 판단, 공고의 직무 해석(하는 일, 누구를 위한 일)에 맞춰 쓰기, 600자 이상 문항은 `[제목]`을 검사 |
| 세부 설명이 길어 요점이 묻힘 | 구체성은 판단 근거·행동·결과에만, 배경은 한 줄로. 쉬운 말과 사람이 쓰는 문장부호로 초안부터 쓰고, 교정은 확정 뒤 한 번만 |
| 글자수 기준이 사이트마다 다름 | 공백 포함·제외·바이트 계산기(한글 자모 분리, 줄바꿈, 이모지 처리)와 초과 시 축약 |
| 확실하지 않은 값 | 글자수 제한·세는 방식 등은 추측하지 않고 사람에게 묻기 |
| 판단과 규칙 처리가 섞임 | 판단·글쓰기는 LLM 스킬, 계산·수집·저장은 테스트된 Python으로 분리 |

## 실제 데이터로 검증하며 고친 것

- **DART 공시 직원 수 중복 집계:** 회사마다 합계 행 형식이 달라 직원 수가 두 배가 되거나 평균 급여가 비었습니다. 실제 사업보고서로 확인해 우선순위 규칙(전체 합계 → 합계 부문의 남·여 → 남·여 행)을 만들었습니다.
- **공시 등록명 불일치:** "SK브로드밴드"가 "에스케이브로드밴드"로 등록돼 있었습니다. 비교할 때 영문 약자를 한글 읽기로 바꿉니다. 이름이 일부만 같으면 자동으로 고르지 않고 후보로 보여 줍니다.
- **Notion API 응답 형식:** 블록 추가 응답이 새 블록이 아니라 부모의 전체 목록이었습니다. 추가 전후 목록을 비교해 새 블록을 찾고, 다시 저장해도 사용자가 쓴 메모와 상태는 보존합니다.
- **iframe 안의 공고 본문:** 상세요강이 iframe 안에 있어 본문이 비는 사이트가 있었습니다. iframe 글자와 공고 이미지 주소까지 함께 읽도록 고쳤습니다.
- **이미지로 된 채용 공고:** 세로로 긴 공고 이미지를 조각내 멀티모달 LLM이 읽고, 주요 업무·자격 요건·우대 사항으로 정리합니다.
- **API 제약:** 개인에게 막힌 API는 대체 수집원(뉴스 → RSS)으로 바꾸고, 키가 없거나 응답이 이상해도 전체가 멈추지 않고 JSON 오류로 알립니다.

## 구조

| 경로 | 내용 |
|---|---|
| `.claude/commands/apply.md` | `/apply` 전체 흐름 |
| `.claude/commands/review.md` | `/review` 직접 쓴 자소서 평가·첨삭 |
| `.claude/skills/` | 기업 분석, 문항 추출, 강조 전략·경력기술서, 자소서 초안, 문항 유형 가이드, 자소서 첨삭 |
| `.claude/agents/essay-strategist.md` | 문항별 설계표를 내는 채용 컨설턴트 에이전트 (`/apply`에서 두 관점으로 동시에 호출) |
| `src/career_ai/` | Python CLI: 글자수 검증, DART·뉴스·공고 수집, 기업 규모 판단, 조건 필터, Notion 동기화, 이미지 처리 |
| `examples/data-template/` | 개인 데이터 저장소 뼈대 (경험 기록 양식) |
| `examples/sample-data/` | 가상 인물의 예시 데이터와 샘플 공고 결과 |
| `tests/` | pytest (네트워크 없이 도는 테스트, 실제 API 확인용 `-m live`) |

개인정보(경험 기록, 지원 내역)는 이 저장소가 아니라 **별도 비공개 저장소**에 두고 `CAREER_DATA_DIR`로 연결합니다.

## 설치

필요한 것: git, [uv](https://docs.astral.sh/uv/), [Claude Code](https://claude.com/claude-code)

```bash
git clone https://github.com/JoowonMun/career-ai-agent.git
cd career-ai-agent
uv sync
uv run playwright install chromium
cp .env.example .env                       # CAREER_DATA_DIR, API 키
uv run career-ai init-data ../career-ai-data   # 개인 데이터 폴더 뼈대
uv run career-ai config                    # 데이터 폴더 경로가 나오면 정상
```

교정에 쓰는 플러그인(터미널에서):
```bash
claude plugin marketplace add epoko77-ai/im-not-ai
claude plugin install humanize-korean@im-not-ai
```

| 키 (`.env`) | 용도 | 필수 |
|---|---|---|
| `DART_API_KEY` | 기업 공시, 직원 수, 평균 급여 | 권장 |
| `NOTION_TOKEN`, `NOTION_DATA_SOURCE_ID` | 지원 현황 정리 | 선택 |
| `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET` | 뉴스 (없으면 RSS) | 선택 |
| `SARAMIN_API_KEY`, `WORK24_API_KEY`, `DATA_GO_KR_API_KEY` | 공고 검색, 비상장 기업 규모 | 선택 |

## 사용법

1. 개인 데이터 폴더의 `experience/`에 경험 기록을 채웁니다: `profile.md`, `career-master.md`(기본 경력기술서), `projects/*.md`(프로젝트별 상황·과제·행동·결과), `motives.md`(지원 동기와 이직 이유).
2. Claude Code에서 `/apply`에 공고 URL이나 원문을 넣습니다. 자소서 문항이 없는 공고는 확인한 뒤 자유 문항으로 씁니다.
3. 분석 후, 스토리라인 후보, 문항별 설계표, 초안 후에 확인을 요청합니다.
4. 결과는 `applications/{회사}_{공고ID}/`에 저장되고 Notion 표에 한 줄로 정리됩니다. `final.md`를 복사해 지원서에 붙여넣습니다.
5. 직접 고친 문항은 `/review <지원 폴더 이름> [문항 번호]` 뒤에 붙여넣어 첨삭을 받습니다.

## 개발

```bash
uv run pytest        # 네트워크 없이
uv run pytest -m live  # 실제 API 확인 (키 필요)
uv run ruff check .
```

이 프로젝트는 Claude Code를 활용해 설계·구현했습니다. 요구사항 정의, 설계 결정, 실제 데이터 검증과 수정 방향은 직접 판단했고, 구현은 테스트를 먼저 쓰는 방식으로 진행했습니다.
